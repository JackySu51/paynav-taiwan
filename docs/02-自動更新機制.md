# 02 ｜自動更新機制（R2 + GitHub Actions）

> 這份文件原本叫「自動更新與財政部 API」，涵蓋財政部電子發票 API 的申請流程。
> 2026-08 決定不串接財政部 API（個人開發者依規定申請不到，需要 ISO 27001
> 認證，只發給企業組織），相關內容、程式碼、Worker 全部移除。這份文件只保留
> 跟財政部無關的兩件事：R2 熱更新、GitHub Actions 定時檢查。

這份文件處理兩件事：

1. **R2**：把會變動的資料（回饋規則、門市資料）放在雲端，改資料不用重新部署網站
2. **GitHub Actions**：定時檢查規則有沒有過期，過期就自動開 Issue 提醒你

全部都是選用的。跳過這份文件，App 一樣能跑，只是資料要手動更新、規則過期要自己記得檢查。

## 先搞懂資料是怎麼流的

```
  GitHub repo                                      Cloudflare R2
  public/data/*.json  ───（手動或 Actions 推送）───►  paynav-data
  （原始檔、有版本紀錄）                              （公開讀取的 JSON）
                                                          │
                                                          ▼
                                                  使用者的手機 App
                                                  抓不到就用內建檔案
```

**重點**：App 讀資料的順序是「R2 → 內建檔案」。所以 R2 掛掉、使用者離線、或你根本沒設定 R2，App 都還是能用內建那份，只是資料舊一點。這是刻意設計的，不要拿掉。

---

## Part A：Cloudflare R2（放資料的地方）

### A-1 建立儲存桶

1. Cloudflare 後台 → 左側 **R2 Object Storage** → **Create bucket**
2. Bucket name 填 `paynav-data`
3. Location 選 **Automatic**
4. 按 **Create bucket**

> R2 免費額度每月 10 GB 儲存 + 100 萬次讀取。這個 App 的 JSON 只有幾十 KB，一輩子都用不完。

### A-2 開放公開讀取

App 要能直接讀這些 JSON，所以要開公開存取。

1. 進入 `paynav-data` bucket → **Settings**
2. 找到 **Public access** → **R2.dev subdomain** → **Allow Access**
3. 輸入確認文字後，會得到一個網址，長得像
   `https://pub-abc123def456.r2.dev`

**把這個網址記下來**，等一下要填進 App 設定。

> 正式一點的做法是綁自訂網域（Settings → Custom Domains），例如 `data.你的網域.com`，速度和穩定度都更好。r2.dev 網址適合先跑通流程。

### A-3 先手動丟一次檔案

在 bucket 頁面按 **Upload**，把 `public/data/` 裡的檔案拖進去：
`rules.json`、`stores.json`

上傳後用瀏覽器打開 `https://pub-你的代號.r2.dev/rules.json`，看得到 JSON 內容就成功了。

### A-4 告訴 App 去哪裡拿

**本機測試**：在專案根目錄建一個 `.env.local` 檔案（複製 `.env.example` 改名），填：

```
VITE_DATA_BASE_URL=https://pub-你的代號.r2.dev
```

存檔後重跑 `npm run dev`。

**線上網站**：到 Cloudflare 專案 → **Settings** → **Environment variables** → **Add variable**

| Variable name | Value | Environment |
| --- | --- | --- |
| `VITE_DATA_BASE_URL` | `https://pub-你的代號.r2.dev` | Production |

加完要**重新部署一次**才會生效。

## Part B：GitHub Actions 的定時任務

`.github/workflows/refresh-data.yml` 每天台北時間早上 8 點會：

1. 跑 `scripts/check-rules.mjs` 檢查有沒有規則過期或即將到期
2. 資料有變就自動 commit 推回 repo
3. 有規則 30 天內到期 → **自動幫你開一個 GitHub Issue**，列出是哪幾張卡

### 要設定的東西（都是選用的）

到 repo → Settings → Secrets and variables → Actions：

**Secrets 頁籤**（機密，只有要用 R2 同步才需要）：

| Name | 值 | 沒設會怎樣 |
| --- | --- | --- |
| `CLOUDFLARE_API_TOKEN` | Cloudflare token | R2 同步那段會失敗（跳過，不影響其他步驟） |
| `CLOUDFLARE_ACCOUNT_ID` | Cloudflare Account ID | 同上 |

**Variables 頁籤**（可公開）：

| Name | 值 | 意思 |
| --- | --- | --- |
| `ENABLE_R2_SYNC` | `true` | 開啟「自動把 JSON 同步到 R2」 |
| `VITE_DATA_BASE_URL` | R2 公開網址 | build 時用 |

### 手動測試一次

不用等到明天早上。到 repo → **Actions** 頁籤 → 左側選「每日資料更新與規則到期提醒」→ 右邊 **Run workflow** → 綠色按鈕。

跑完點進去看每一步的 log，紅色叉叉會告訴你哪裡卡住。

## 更新回饋規則的完整流程（你以後每個月會做的事）

1. 收到 GitHub Issue 提醒，或自己想改
2. 打開 `public/data/rules.json`，改數字和 `valid_until`
3. 跑 `npm run check:rules` 確認沒打錯
4. `git add . && git commit -m "更新 8 月回饋規則" && git push`
5. 剩下的自動發生：Actions 檢查 → 部署 → 同步到 R2 → 使用者下次開 App 就看到新規則

**使用者不用更新 App**，因為資料是從 R2 讀的。這就是把資料和程式碼分開的好處。

| 服務 | 免費額度 | 這個 App 大概用多少 |

| Cloudflare R2 | 10 GB 儲存、100 萬次讀取／月 | 幾十 KB、幾千次讀取 |
| GitHub Actions | 公開 repo 免費；私有 repo 每月 2000 分鐘 | 每月約 10 分鐘 |
