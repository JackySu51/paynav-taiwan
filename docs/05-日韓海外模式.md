# 05 · 日韓海外模式

你問「台灣支付工具在日本、韓國的優惠比較」值不值得做。**兩邊都值得，而且韓國的價差可能比日本更大。**

日本走的是 PayPay 跨境掃碼，韓國走 Paybooc（TWQR）與 ZeroPay 兩條網路。兩邊都有「選對付款方式就省下 1.5% 手續費」的結構，韓國的電支活動回饋甚至常常拉到二三十趴。

---

## 為什麼日本值得做

日本是台灣人出國最多的地方，台灣電支可以直接掃當地店家的 PayPay QR。

<!-- 以下事實查證日期 2026-08，會變，出發前請自己再確認一次 -->

目前支援掃日本 PayPay 店家 QR 的台灣支付：

| 台灣支付 | 加入時間 |
| --- | --- |
| 街口支付 | 2023/10 |
| 全支付 | 2023/10 |
| 玉山 Wallet | 2023/10 |
| 一卡通 iPASS MONEY | 2024/11 |
| 台新 Pay+ | 2026/02 |
| 全盈+PAY | 2026/02 |

**關鍵好處是省下 1.5% 的國外交易服務費**——走這條路是「台灣電支帳戶直接付款」，不經過信用卡國際組織，所以沒有那筆費用。PayPay 在日本的加盟店超過百萬家，涵蓋便利商店、藥妝、百貨、家電，還有很多原本不收信用卡的居酒屋和拉麵店。

對一個「幫你決定用哪個付款方式」的 App 來說，這是最有價值的海外場景：**同一間店，選錯方式就是多付 1.5%。**

## 韓國：我上一版寫錯了

上一版我寫「韓國沒有台灣電支的跨境方案，只能靠信用卡」。**這是錯的**，已經更正。

台灣電支在韓國走兩條不同的網路：

| 台灣支付 | 韓國合作方 | 主要通路 |
| --- | --- | --- |
| 台灣 Pay | BC 卡 Paybooc（TWQR） | 超商、大創、連鎖咖啡、百貨、免稅店 |
| 悠遊付 | BC 卡 Paybooc（TWQR） | 同上 |
| icash Pay | BC 卡 Paybooc（TWQR） | 同上 |
| 全支付 | ZeroPay / HIVEX | ZeroPay 店家、**傳統市場** |
| LINE Pay | 指定合作店家 | CU、樂天、新世界、INNISFREE 等 |

**這件事對推薦邏輯的影響很大**，因為不同支付走不同通路網：在傳統市場只有全支付能用（走 ZeroPay），在大創則是台灣 Pay／悠遊付／icash Pay 能用（走 Paybooc），LINE Pay 在傳統市場不通。所以韓國的通路從 5 個細分成 10 個，每條規則都對應到實際的通路網。

實作時抓到自己的一個 bug：第一版的通路重映射把範圍套太寬，導致傳統市場也跳出悠遊付 18.5%。修正後傳統市場只剩全支付居首，這才是對的。

另外這些支付在韓國**都是帳戶扣款、不能綁信用卡**（icash Pay 明確只能用自家帳戶或綁銀行帳戶），所以回饋屬於支付工具本身，不屬於任何一張卡。這也是為什麼資料裡多了一張虛擬的「電支帳戶（免綁卡）」。

**回饋活動的波動極大。** 台灣 Pay 曾經有 20%，也曾經整段時間停辦；悠遊付與 icash Pay 的暑假活動動輒二三十趴。這些數字放進 App 一定要標活動期限，並在畫面上寫清楚「出發前查一次官網」。資料裡這些規則的 `valid_until` 都設在活動結束日，`npm run check:rules` 會在到期前 30 天提醒你。

## 資料怎麼組織的

**通路加了 `region` 欄位**（`TW` / `JP` / `KR`），沒寫的視為台灣：

```json
{ "id": "jp_donki", "name": "唐吉訶德 Don Quijote", "category": "general", "region": "JP" }
```

日本通路：`jp_general`、`jp_convenience`、`jp_drugstore`、`jp_donki`、`jp_supermarket`、`jp_restaurant`、`jp_department`

韓國通路（依實際通路網細分）：`kr_general`、`kr_convenience`、`kr_daiso`、`kr_cafe`、`kr_cosmetics`、`kr_supermarket`、`kr_department`、`kr_dutyfree`、`kr_market`、`kr_restaurant`

**支付工具加了 `overseas` 欄位**，標明它能在哪些海外地區用：

```json
{ "id": "jkopay", "name": "街口支付", "overseas": ["JP"] }
```

**回饋規則用通路 id 指定海外**：

```json
{
  "payment_method": "esun_wallet",
  "channels": ["jp_general", "jp_convenience", "jp_donki"],
  "base_reward_pct": 1,
  "extra_reward_pct": 3,
  "cap_amount_monthly": 500,
  "note": "玉山 Wallet 掃日本 PayPay，免 1.5% 海外手續費"
}
```

## 一個必須修掉的陷阱

原本的引擎有個嚴重問題：`channels: ["all"]` 會跨國生效。

結果是玉山 Unicard 的「行動支付自選 3%」會出現在東京的超商推薦裡，悠遊付和 icash Pay 也會被列出來——**那些在日本根本刷不到**。使用者照著推薦掏出手機，站在櫃檯前發現付不了。

修法（在 `src/utils/rewardEngine.ts`）：

- `["all"]` 的語意明確定義為「台灣所有通路」，不是全世界
- 地區不是台灣時，只採用明確列出 `jp_` / `kr_` 通路的規則
- 而且該支付工具必須在 `overseas` 裡標明支援那個地區

## 使用者怎麼切換

三種方式，優先順序如下：

1. **GPS 自動判斷** — 走到東京新宿，定位命中 `jp_convenience` 的示範點位，畫面自動變成日本模式
2. **手動下拉** — 頂部通路徽章點開，最上面有 🇹🇼 🇹🇼 / 🇯🇵 / 🇰🇷 地區切換，選了地區再選通路
3. **出國前先看** — 在台灣就可以手動切到日本，先研究要帶哪張卡、要先開通哪個 App

進入海外模式時，畫面上會多一段提示，說明該地區的付款策略（日本走 PayPay 跨境免手續費、韓國要留意 DCC）。

## 海外規則要注意的三件事

**1. 那 1.5% 國外交易服務費**
台灣發卡機構對海外刷卡收約 1.5%（Visa/Mastercard 的國際清算費 + 銀行加收）。所以一張「海外 3% 回饋」的卡，實質只有 1.5% 左右。有些卡會折抵這筆費用，那才是真的 3%。`rules.json` 的 `note` 欄位請務必寫清楚是哪一種——這是海外回饋最容易誤導人的地方。

走台灣電支掃 PayPay 沒有這筆費用，這也是為什麼它常常比刷卡划算。

**2. 拒絕 DCC（台幣結帳）**
店家問「要用台幣還是日圓結帳」，一律選當地幣別。選台幣是動態貨幣轉換，匯率通常比銀行差 3% 以上，而且**國外交易服務費照收**。這件事值得寫進 App 的海外提示裡。

**3. 匯率換算不要自己算**
不要在 App 裡放即時匯率然後幫使用者算「這樣是多少台幣」——匯率要即時 API、刷卡當天與請款日的匯率還不同，算出來一定跟帳單有落差，使用者會覺得你的 App 不準。比回饋率就好，那是確定的。

## 接下來怎麼擴

1. **門市資料**：已經做成可下載的地標包，日本 7 個都市、韓國 5 個都市，用 `npm run packs:build` 從 OpenStreetMap 產製，見 `docs/06`。
2. **卡片海外規則**：現在的海外數字是示範值。實務上要盯的是各卡的「海外加碼活動」，那是**每季都在換**的東西，記得加進 `promo-sources.json` 的監控清單。
3. **其他國家**：資料結構已經支援，加 `region` 就好。下一個值得加的大概是泰國（Alipay+ 網路覆蓋較廣）與新加坡。日本之外，跨境掃碼的生態都還很零碎，先確認真的有明顯價差再加。
